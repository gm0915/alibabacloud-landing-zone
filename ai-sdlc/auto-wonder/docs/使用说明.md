# AutoWonder 使用说明

按下面顺序完成一次空间接入。前一步没做完，后面的数字员工无法拉代码、也无法上线接单。

建议一个工作空间只保留一套正在使用的 SDLC 流程。流程从模版间创建后，会自动生成小队和数字员工，并把当前空间里的仓库全部绑上。

## 1. 创建工作空间

工作空间按业务聚合，不按仓库拆分。设备服务、人群服务、风控服务这类相互独立的业务，可以合并到一个空间。同一个业务的前端、后端、接口、关联业务仓库放进同一个空间。

1. 在工作空间列表点击「创建新工作空间」。
2. 填写工作空间名称和描述。名称用业务名，例如「计价业务-中台」。
3. 进入该空间后再配置仓库、流程、数字员工和执行器。

需要其他人协作时，由管理员在「成员管理」中按昵称或登录名添加。只读只能查看，读写可以建单和启动交付，管理员可以改流程、仓库、数字员工和执行器。

## 2. 配置空间仓库

在空间内打开「仓库」，把这一业务相关的 Git 仓库都加进来。

添加时：

- **仓库名称**只填单级目录名，不要填 `group/repo`，也不能包含 `/`、`\`、`.`、`..`。
- **仓库地址**填完整克隆地址，例如 `git@git.example.com:group/repo.git`。
- **默认分支**填仓库真实默认分支 `master`。

### 执行器主机的 Git 权限

数字员工通过执行器主机拉代码、提交分支。不要使用个人 Git 账号，每组单独准备一个 Git 账号，并把公钥配到该账号上。

在执行器主机上生成密钥（一路回车即可）：

```bash
ssh-keygen -t ed25519 -C "autowonder-executor" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

然后：

1. 在 Git 平台创建一个独立账号。
2. 把上一步打印的公钥配到该账号。
3. 在执行器主机上用该账号试克隆一个仓库，确认免密成功后再启动执行器。

多台执行器主机各自生成自己的密钥。不要把同一把私钥拷到多台机器。

## 3. 配置流程

仓库加完后，进入「SDLC 流程」，打开「模版间」，选择与业务匹配的模版，点击「基于此模版创建」。

创建时会自动生成小队、数字员工和 SDLC，并给这些数字员工绑定空间内已有的全部仓库。先把仓库加完，再从模版创建流程。

一般一个空间只用一个流程。模版越完整，流转阶段越多。按业务选择：

| 业务 | 建议模版 | 规模 |
| --- | --- | --- |
| 一般业务 | 开发+评审双人组 | 开发、评审 2 人 |
| 核心业务 | 标准研发交付小队 | 开发、评审、测试 3 人 |
| 单人试用 | 独立开发者 | 1 人 |
| 需求澄清、项目管理、DBA 等也要进流程 | 全链路研发协作小队 | 7 个角色 |

模版不够用时可以自己新建 SDLC，并手工维护步骤、检查项和准出策略。自定义流程步骤多、门禁细，配置和后续维护都更重，没有特殊需要时用模版。

创建后到流程列表确认状态为已启用。启用后步骤不可再改；要改步骤需先禁用。

实际业务不建议使用 独立开发者 和 全链路研发协作小队。

## 4. 调整数字员工

流程创建后，到「数字员工 → 管理」查看自动生成的数字员工。默认每个人对空间内全部仓库都有写权限。按角色收紧，避免评审、测试角色直接改代码。

打开数字员工详情，在「仓库权限」中调整：

- 需要改代码并提交的角色使用「读写」，并填写「允许提交的分支」。
- 只需要阅读代码的角色改为「只读」。只读不需要提交分支。
- 留空表示不限制分支。限制开发角色时填写 `feature-*`。

分支规则最多 32 条。通配符只能有一个，并且必须放在末尾。`feature-*`、`feature/*`、`develop` 都合法；`feature/**`、`*/feature` 不合法。

仓库权限和能力的修改进入草稿。改完后提交审核并发布，后续任务才会使用新配置。名称和头像保存后立即生效，不走审核。

## 5. 配置执行器

每个数字员工配置一台执行器。执行器是数字员工实际跑任务的进程，不上线就不会接单。

当前测试在 Windows 上无法正常运行。执行器主机使用 Linux。

### 主机环境

在启动执行器之前，在 Linux 主机上准备：

- **Qoder CLI**（命令为 `qoderclicn`）。到 [Qoder CLI](https://qoder.cn/cli) 按官方说明[安装](https://docs.qoder.cn/cli/installation)，安装后执行 `qoderclicn` 完成登录。
- **Git**。确认第 2 节的独立账号已经能免密克隆仓库。
- **JDK**。版本与业务仓库的构建要求一致。
- **Maven 私服**。按团队私服地址配置该用户的 `~/.m2/settings.xml`，使业务仓库能拉到内部依赖。本文不写具体私服地址。

### 在平台登记并启动

1. 打开「数字员工 → 执行器」，点击「新建执行器」。
2. 选择归属的数字员工，客户端类型选择 Qoder CLI CN。如果用的是国际版qodercli，则选择 Qoder CLI
3. 记忆模式选「平台记忆」。最大并发按机器能力设置，默认 5。
4. 保存启动配置。配置变更后必须用新的启动命令重新启动。
5. 复制 **macOS / Linux** 启动命令，到执行器主机上执行。不要使用 Windows 命令。
6. 回到执行器列表，确认该执行器状态变为「在线」。

启动命令里包含执行器 Token，只在创建时完整展示，由管理员保管，不要写入仓库或聊天记录。一个数字员工对应一个执行器；换机器时先停掉旧进程，再用新命令启动。

## 6. 配置能力

当前测试中，只在 Qoder CLI 本机配置的技能无法被数字员工加载。把要用的技能加到平台，再绑到数字员工。

1. 打开「能力」。
2. 上传技能目录或 ZIP。根目录需要有 `SKILL.md`，系统读取其中的 `name` 和 `description`。单个包最多 500 个文件，压缩包和解压后都不超过 100 MB。
3. 打开对应数字员工，在「能力配置」中「添加能力」，选中刚上传的技能。
4. 提交审核并发布。

平台 MCP 已内置，任务派发时自动装载，不必再手工绑定，也不要配置个人长期 Token。

## 配置完成

执行器在线、数字员工已发布后，即可在「工单」中创建工单并按该流程交付。数字员工只会在自己有权限的仓库上工作，提交时也只会落到「允许提交的分支」所匹配的分支。
